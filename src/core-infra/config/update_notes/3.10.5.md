# 3.10.5 — What each agent's account can reach

## Maintenance after this update

From this release no agent's account can read `/etc/versa-agi/setup.ini`, a config or `.env` file under `/etc/versa-agi/`, or another agent's home folder, and none can write a database. Agents get what they need through `agictl`, as before. A cycle's own files are no longer under `/tmp`.

Nothing below is known to be true on this instance. Make the check once and do what its result calls for.

1. **Scripts that read system files directly.** This note went to you only.
   - Check: the scripts in AGi-Tools, and in each project you lead, that run as Script Tasks or that you or another agent run by hand. Does any open `/etc/versa-agi/setup.ini`, a file ending `_config.json` or `.env` under `/etc/versa-agi/`, a database under `/var/lib/versa-agi/`, another agent's home folder, or a file named `/tmp/versa_agi_…`?
   - If one of yours does: it is refused from this release. Change it to get what it needs through `agictl` (a stored credential comes from `agictl organization credential`), then run it once to confirm it works.
   - If one belongs to another agent: give that agent one task to change it, and say what done looks like.
   - If none does: there is nothing to do.

2. **Blocked tasks that wake you again and again.** This note went to you only.
   - Check: `agictl task list`. Is any task `blocked` with a due date that has already passed?
   - If one is: it wakes its agent on every pass. Snooze it to when the blocker will be looked at again (`agictl task snooze <id> <minutes>`). If it belongs to another agent, give that agent one task to do the same.
   - If none is: there is nothing to do.

## Tell the Primary User

- This update tightens what each agent's account can reach. No agent account can write a database, read the settings file or an agent's config file (they hold the VersaVoice API token and the provider keys), or enter another agent's home. The lead agent can still enter the other agents' homes, and the shared workspace is unchanged.
- To read `/etc/versa-agi/setup.ini` themselves they now need `sudo`. agitop works as before.
- `agictl execute` run from their own login without `sudo` is no longer accepted. With `sudo` it works as before.
- A package request now shows in the VersaVoice app within about a minute.
- Skills are now loaded whole, with the tool `agictl_load_skill`. Before, a skill read with `cat` was cut at the tool output limit, so long skills were followed in part. 48 commands in the skills that were refused as written are corrected.
- `agictl system config get` shows `[hidden]` in place of every key and token.
- When they put an agent in touch with a person for a project or a task and that person asks for something else, or for something the system is not meant to do, the agent declines and reports to you. You approve what fits what you have already established with them; when you are not sure, you ask them once and use their answer for similar requests afterwards. A suspicious request is declined and always reported to them (skill `task_routing.md`).
- On a call, when the voice said goodbye and the call stayed open, they had to ask again. Now you get a `quiet check` message after about 6 seconds of silence and can close the call (skill `live_call.md`, section 3).
- The result of the two checks above: which scripts were changed, and which blocked tasks were snoozed, if any.
