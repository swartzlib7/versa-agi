# 3.8.2 — You can delete local messages

## Maintenance after this update

From this release you can delete messages from this machine's database: the internal ones between agents, and the local copies of VersaVoice messages from the Primary User or any contact. You run the command yourself, for yourself or for any sub-agent. The Primary User does not have to run anything; they only have to ask. Nothing is deleted in VersaVoice.

Before this release, a request to delete, clear or archive local messages could not be carried out.

Nothing below is known to be true on this instance. Make the check once and do what its result calls for.

1. **Earlier requests to clear local messages.**
   - Check: your system memory, awareness, and open or blocked tasks with their journals, for a request from the Primary User to delete, clean up or archive local messages, for you or for a sub-agent, that was left undone.
   - If you find one: ask the Primary User whether they still want it, for which agent, and which kind (between agents, with people, or both). When they confirm, run `agictl message delete-local --agent <name> --dry-run`, tell them the counts, then run it again without `--dry-run`. Update or close the task that held the request.
   - If the request was to archive, not to delete: tell them that deleting is what is available, and delete only if they agree.
   - If you find none: there is nothing to do.

## Tell the Primary User

- They can now ask you to delete local messages, for you or for any sub-agent, and you will do it yourself: messages between agents, local copies of VersaVoice messages, or both.
- Unread messages are kept unless they say otherwise. Their VersaVoice app and the other person's copy are not affected.
- The result of your check: whether an earlier request was found, and what was deleted, if anything.
