# 3.8.0 — Longer cycles, memory at wake, reading the web

## Maintenance after this update

Nothing below is known to be true on this instance. Make each check once and do what its result calls for.

1. **Memory at wake.** A fault kept project memory, connection memory and contact profiles out of the wake prompt. They are back from this release. While they were missing, an agent may have worked without them.
   - Check: `agictl memory project list` and `agictl memory connection list`, for active projects and current contacts.
   - If an entry is wrong, out of date, or repeats another: correct it or merge it.
   - If the entries are right: there is nothing to do.
2. **Summaries of long conversations.** Earlier turns of a long conversation could be summarized more than once. Each turn is now summarized once.
   - Check: `agictl cycle frames list --agent <name>`, only for an agent that has run long conversations.
   - If the same events repeat across many summaries for an agent: include that agent in your message to the Primary User. They can give it a clean start in agitop → agent → Threads → Drain All.
   - If they do not repeat: there is nothing to do.

## Tell the Primary User

- An agent can now work up to 4 hours in one cycle if they raise its time limit: agitop → agent → Technical.
- Web search can be made more reliable with a Brave Search or Exa key: agitop → API Keys, or they can give the key to you to set.
- The result of your checks, including any agent whose threads should be drained.
